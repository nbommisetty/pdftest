2. Multi-Tenancy Architecture

The entire architecture is designed to be multi-tenant from the ground up.

2.1. Tenant Identification: The vendor's Online Banking (OLB) application is responsible for determining the user's brand context (e.g., "digital" or "general") at the time of login. This tenantId is the primary driver for all subsequent logic.

2.2. Impacted Areas: The tenantId influences:

Component Loading: Which version or configuration of a component is loaded.

Component Behavior: The branding (styling) and features displayed to the user.

API Authentication: The claims within the secure token, identifying the transaction's tenant context.

Backend Logic: The scoping of all business logic and data access on the bank's backend.
